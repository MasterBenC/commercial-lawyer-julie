# 本地知识库挂载（personal-kb）

Julie v0.2 在主张中国大陆民商法或税法黑字规则前，应优先检索已挂载的私有知识库 **personal-kb**（仓库：`MasterBenC/personal-kb`，**不随本 Skill 公开发布**）。本文件说明挂载方式、只读路径与引用状态；Skill 在知识库未挂载时仍可工作，但不得编造条文原文。

## How the host mounts / 宿主如何挂载

任选其一（优先级建议从上到下）：

1. 环境变量 `PERSONAL_KB_ROOT` 指向 personal-kb 仓库根目录（含 `_index.md` 的那一层）。
2. 与本 Skill 目录同级的克隆：`../personal-kb`（即 Skill 根目录旁的 sibling clone）。
3. 用户在宿主配置中声明的绝对路径。

可选二级库（**仅当用户明确问及高新 / 专精特新 / 单项冠军 / 申报辅导时**再挂载，非 Julie 默认依赖）：

- `MIIT_QUALIFICATION_KB_ROOT` 或 sibling `../miit-qualification-kb` → 私库 `MasterBenC/miit-qualification-kb`。

挂载探测失败时：在输出中说明「本地 personal-kb 未挂载或不可读」，继续做商业判断，并对拟引用的黑字规则统一标记 `needs_verification`；**禁止虚构条文编号、条文正文或司法解释标题**。

## 读取顺序

1. 打开 `personal-kb/_index.md`（及可选 `AGENTS.md`），确认域目录存在。
2. **只打开任务所需子域**；禁止默认加载整个仓库。
3. 再按下方主题表打开具体法条 / 司法解释 / 规章文件。

## Citation format / 输出中的引用格式

对从 personal-kb 读到的条文或解释，在结论中写：

```text
依据：personal-kb/<相对路径>#条号或标题
来源状态：kb | verified | needs_verification | unavailable
```

状态含义（与 `jurisdiction-source-policy.md` 对齐并扩展）：

- `kb`：已从已挂载 personal-kb 对应文件读出；适合内部分析与草稿。中高风险或对外正式意见时，应再经权威一手来源升级为 `verified`。
- `verified`：已通过权威一手来源（如国家法律法规数据库 flk.npc.gov.cn 或官方发布页）核验。
- `needs_verification`：尚未完成库检索或官方核验；**知识库缺失时强制使用此状态（或 `unavailable`）**，不得假装已引用。
- `unavailable`：核验失败或无法取得可靠来源。

## If KB is missing / 知识库未挂载

- 明确告知用户 personal-kb 不可用。
- 仍可给出商业风险判断、谈判要点与模板草案。
- 凡拟依赖具体法条、司法解释或规章原文处，标记 `needs_verification`（或核验失败时的 `unavailable`）。
- **Do not invent article text.** 不得编造条号、条文正文、文号或解释名称来填补空白。

## 自建本地知识库最小目录与 `_index.md` 脱敏示例

外部用户可以不依赖 `MasterBenC/personal-kb` 与 `MasterBenC/miit-qualification-kb`，用自有法务知识库满足同一挂载契约。**私有库正文始终不随本 Skill 分发**：本仓库只提供挂载方式与引用规则，不打包、不镜像任何库内文件；本节的目录名和示例内容仅示范结构。

### 最小目录

```text
my-legal-kb/
├── _index.md                        # 必填：域目录清单、每域用途、维护人、最近校核日期
├── 01-民商法/
│   ├── 法条/民法典/合同编.md
│   ├── 法条/现行商法/公司法.md
│   └── 司法解释/
├── 02-税务/                          # 涉税商事争点才读
│   ├── 法条/
│   ├── 行政法规/
│   └── 部门规章与规范性文件/
└── 03-交汇专题/                      # 可选：股权+税、重组、家办等交汇结构
```

- 顶层目录名沿用 `01-民商法` / `02-税务` / `03-交汇专题`，本文件上方主题表的映射即可直接复用；自有库命名不同时，须在 `PERSONAL_KB_ROOT` 指向的根下建同名目录做映射，不要把 Skill 指向仓库外的散装文件。
- 客户案例类目录（如 `05-客户案例-脱敏/`）即使存在，也**不得默认加载**；需要时逐次由用户明示。
- 每个法条文件建议保留头部字段：标题 / 发布机关 / 文号 / 生效日期 / 来源 URL / 核验日期，便于后续升级为 `verified`。
- 只需民商法一个域时，最小可用集是 `_index.md` + `01-民商法/`；税务与交汇目录缺失不阻断运行。

### 使用自有库时的强制规则

- 未挂载或不可读：一律对拟引黑字规则标 `needs_verification`（核验失败时用 `unavailable`），并明确告知用户本地库不可用；不得编造条号、条文正文、文号或解释名称。
- 命中自有库：只能记为 `kb`，含义是「已从本机库读出」，不等于完成官方核验；中高风险或对外正式意见须按 `jurisdiction-source-policy.md` 升级为 `verified`。
- 示例与占位内容（包括本节的 `_index.md` 示例）不得作为条文依据引用，只能用于说明格式；虚构示例不得被复述进正式意见。
- 挂载只改变检索范围，不改变本文件与 `privacy-safety.md` 的数据最小化要求：不上传库内文件，不默认加载案例目录。

## Sync / 时效声明

personal-kb 中的法条底稿可能滞后于官方最新文本。正式对外法律意见、诉讼材料或监管回复前，须在 [国家法律法规数据库](https://flk.npc.gov.cn) 等权威一手来源复核，并将状态升级为 `verified`（记录发布机关、生效日期、URL、核验日期）。知识库命中**不能**单独证明合同适用法律、管辖法院或仲裁地。
